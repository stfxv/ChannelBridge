# ChannelBridge

多チャンネルのオーディオインターフェースから必要な入力を選び、2チャンネルの仮想マイク **ChannelBridge Mic** へ送るmacOSアプリである。正式版はRustで実装したアプリと独自HALドライバを使用し、BlackHoleやLadioCastを必要としない。

## 導入

`dist/ChannelBridge-Rust.pkg`を開いてアプリとドライバを導入し、Macを再起動する。アプリは`/Applications/ChannelBridge.app`に配置される。旧通常版と同じ機器UID・設定先を使用する。導入前のバックアップと復帰手順は[RUST_MIGRATION.md](RUST_MIGRATION.md)を参照する。

入力機器・入力チャンネル・mono/stereo/mixを選び、マイク使用を許可する。送出開始前から入力レベルを確認できる。通話アプリ側は **ChannelBridge Mic** を入力に選ぶ。選択した入力のdBFS、物理入力形式、仮想マイク形式を表示する。仮想マイクと内部PCMは32bit floatであり、物理入力24bitを表示する場合もある。音声の録音保存は行わない。

Rustの開発規則と自動検査は[RUST_STYLE.md](RUST_STYLE.md)を参照する。

## ビルド

macOS 13以上、Xcode Command Line Tools、Rust 1.98.1（最低対応1.85.0）、Apple Silicon/IntelのRustターゲットを使用する。

```sh
bash scripts/test.sh
bash scripts/build.sh
```

通常版Universalアプリとインストーラを`dist/`へ生成する。ビルドはインストールや音声サービスの再起動を行わない。試験版は`bash scripts/package-rust-test-app.sh`で別UID・別設定先へ生成する。旧Go版のソースと当時のライセンス表示は[削除前のGit履歴](https://github.com/stfxv/ChannelBridge/tree/f261f65d86d995b67b02942148f067d01365f148)に保存されている。

## 検証範囲

0.5.8では、古い世代の音声フレームを破棄した処理量もFIFOの転送予算へ計上するよう修正した。旧Go/C版のビルド・配布経路を撤去し、Rust版へ統一した。通常・productionの各131件のワークスペーステストとUniversal配布物の検査を実施した。FIFOの1回の読み出しは残予算を超える場合があり、厳密な実時間期限の保証ではない。実機音声品質の追加確認は行っていない。

0.5.7では、48 kHz・1024フレームなどの出力条件で初回の蓄積量が不足し、音声の欠けを繰り返す問題を修正した。再生開始前に、出力1回分と補間に必要な入力が揃うまで保持する。終了前に受け付けた設定保存を完了し、無関係な機器の読み取り失敗があっても有効な入力一覧を表示する。不完全な一覧から切断を推定しない。入力未選択時の自動送出チェックと、配布アプリへの古いファイルの残留も修正した。

0.5.6では「復帰時に自動送出」を追加した。ONにすると、システムのスリープ復帰、または選択した入力機器の再接続後に送出を開始する。初期値はOFFで、設定は保存される。ONにする操作や入力機器の変更だけでは送出を始めない。起動時に入力機器が接続済みの場合も、従来どおり入力確認から始める。ミュートとチャンネル選択は維持する。停止操作は次の復帰まで有効で、同時に検出した自動復旧より手動の停止を優先する。

0.5.5では、ドックや入力機器の切断後に音声経路の終了処理が失敗し、その後のスリープ・復帰通知でも再接続できなくなる問題を修正した。0.5.4の実診断では、CoreAudioが消えた機器に対して`!dev`を返すと、アプリが`Blocked`のままになっていた。修正後はコールバックの実行を禁止し、実行中の処理がないことを確認したうえで再接続を許可する。CoreAudioへの登録解除を確認できない場合は、古いコールバックのメモリを解放せずに保持する。そのため切断のたびに保持メモリが増える場合があり、診断の`retained_io_contexts`でアプリ起動後の累積保持数を確認できる。実行中のコールバック、panic、機器消失以外の終了エラーでは再接続を停止する。人工的な切断エラーと並行コールバックを使った回帰試験は通過したが、今回の修正後の実機切断・スリープ復帰と通話アプリへの音声復旧は利用者による確認待ちである。

0.5.5の修正はアプリ側にあり、アプリだけの更新でも既存の0.5.4ドライバと診断プロトコル1で動作する。この更新にHAL音声サービスの再起動は必要ない。通常の統合インストーラには0.5.5ドライバも含む。以下の0.5.4の記録は、その時点の検証範囲である。

0.5.4では、システムのスリープ通知に応じて制御ワーカーが音声経路を解放し、復帰後に入力機器と仮想マイクを再取得する。送出開始・停止、ミュート、入力チャンネルの選択を保持する。画面だけの復帰時は、稼働中の経路を維持して状態を再確認する。有効な入力・出力フレームの処理が2秒停止した場合も自動再接続する。通知を模擬するAppKitテストと実コールバックへの人工入力で確認したが、実機のスリープ復帰は未検証である。

E1x2での2時間通話でケロケロ音が再発しなかったことを利用者が確認した。実HALで44.1〜192 kHzの仮想転送と診断取得を確認した。RME、8時間の実経路、物理レート変更・切断復帰・全対応OS/Intel実行の網羅試験は未検証である。2時間の報告ではmono/stereoの条件は特定していない。正式版への切り替えは利用者の判断によるもので、これらの合格を意味しない。
